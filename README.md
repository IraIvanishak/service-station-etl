# Service station DB

Coursework from my databases lab at Lviv Polytechnic (PZ NULP): an OLTP
database for a network of car service stations, an ETL that loads it into a
star-schema data warehouse, a Go API and a Vue front end to work with both.

![зображення](https://github.com/IraIvanishak/service-station-coursework/assets/110106748/b5ff1919-26ff-4a57-8730-5d170db84ff3)

## Run it

You need Docker, Go 1.22+ and Node 18+.

```sh
make db-up   # Postgres on localhost:5452 with schemas, seed data and ETL procedures
make api     # Go API on http://localhost:3000
make web     # Vue app on http://localhost:5173 (installs npm packages on first run)
```

The warehouse starts empty. Open **Meta** in the app and press **Initial Load**;
after changing data in the app, **Detect Changes** shows what an
**Incremental Load** will pick up.

`make db-reset` drops the database volume and rebuilds it from `db/init`.
`make db-psql` opens psql in the container.

### Configuration

| Variable | Used by | Default |
| --- | --- | --- |
| `DATABASE_URL` | API | `postgres://postgres:postgres@localhost:5452/service_station?sslmode=disable` |
| `HTTP_ADDR` | API | `:3000` |
| `CORS_ORIGINS` | API | `http://localhost:5173,http://127.0.0.1:5173` |
| `VITE_API_URL` | web (`service_station/.env.local`) | `http://localhost:3000` |

## How it works

One Postgres database, four schemas:

| Schema | Contents |
| --- | --- |
| `public` | OLTP tables: stations, employees, clients, cars, repairs, services, parts, stock, supplies. Every table has `created_at`/`updated_at`, kept current by a trigger. |
| `stage` | Copies of the OLTP tables the warehouse is built from. |
| `storage` | The warehouse: `service_dim`, `supplier_dim`, `inventory_dim`, `repair_dim`, `service_repair_dim`, `date_dim`, and two facts, `service_inventory_fact` (parts used in repairs) and `supply_details_fact` (supplies per detail, supplier and date). |
| `meta` | Load history and a description of source and warehouse tables. |

The ETL is a set of stored procedures (`db/init/07`–`11`); `internal/etl`
runs each load in one transaction.

- **Full load**: `stage.transfer_data_to_stage()` copies the OLTP tables to
  stage, `storage.fill_storage_from_stage()` rebuilds the warehouse.
- **Incremental load**: `stage.fill_staging_from_oltp_incremental()` stages
  rows created or updated since the last load (this is what *Detect Changes*
  counts), then `storage.fill_olap_from_staging_incremental()` adds the
  unchanged rows those changes depend on (`stage.stage_referenced_rows()`) and
  upserts dimensions and facts.

Known limitations: deletions in the OLTP tables reach the warehouse only with
a full load; creating a supply changes stock right away, even when it is
still pending.

## Tests

```sh
make test               # unit tests
make test-integration   # + integration tests; needs `make db-up`
```

The integration tests run the real procedures and API against a throwaway
copy of the seeded database (`internal/testdb`). The ETL tests check, among
other things, that warehouse totals match the OLTP data and that an
incremental load ends up identical to a full rebuild. Procedure changes in
`db/init` are picked up automatically; schema changes need `make db-reset`.

## Layout

```
main.go                 starts the API
internal/api            HTTP handlers (Fiber)
internal/etl            runs the ETL procedures in a transaction
internal/config         settings from the environment
internal/testdb         throwaway databases for integration tests
dto                     JSON shapes and row grouping
storage/query           SQL queries; storage/dbs is generated by sqlc (`make sqlc`)
db/init                 schemas, seed data and ETL procedures, run by Postgres on first start
service_station         Vue 3 + Vite front end
```
